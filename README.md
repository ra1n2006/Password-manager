# Password Manager

Консольный менеджер паролей на Python, позволяющий безопасно хранить пароли от различных сервисов, управлять ими и генерировать новые надёжные пароли.

## Возможности

- Создание мастер-пароля для защиты хранилища.
- Авторизация с помощью мастер-пароля.
- Добавление паролей для различных сервисов.
- Просмотр списка сохранённых сервисов.
- Получение пароля для выбранного сервиса.
- Удаление сохранённых паролей.
- Генерация случайных паролей.

## Установка и запуск

Для управления зависимостями используется [uv](https://docs.astral.sh/uv/).

1. Клонируйте репозиторий:

```bash
git clone https://github.com/ra1n2006/Password-manager
```

2. Перейдите в директорию проекта:

```bash
cd Lab1
```

3. Установите зависимости:

```bash
uv sync
```

4. Запустите приложение:

```bash
uv run python src/main.py
```

При первом запуске приложение предложит создать мастер-пароль. Для подтверждения потребуется ввести его повторно.

## Хранение данных

Для хранения информации используется директория `src/data/`.

Директория и находящиеся в ней файлы `master.json` и `storage.json` создаются автоматически при запуске приложения.

- **master.json** — содержит соль и хэш мастер-пароля.
- **storage.json** — содержит названия сервисов и соответствующие им зашифрованные пароли.

Оба JSON-файла и файл `.env` добавлены в `.gitignore`, поэтому они не загружаются в GitHub и отсутствуют в репозитории. При запуске приложения они создаются локально.

Изначально JSON-файлы содержат пустой объект `{}`.

## Безопасность

В проекте используются разные механизмы защиты для мастер-пароля и паролей пользовательских сервисов.

### Мастер-пароль

Мастер-пароль не сохраняется в исходном виде.

Для его защиты используется алгоритм **PBKDF2-HMAC-SHA256** с 600 000 итерациями и случайной солью размером 16 байт.

При создании мастер-пароля:

1. Генерируется случайная соль.
2. На основе мастер-пароля и соли вычисляется хэш.
3. В `master.json` сохраняются соль и полученный хэш.

При авторизации введённый пароль хэшируется с использованием сохранённой соли. Полученный результат сравнивается с сохранённым хэшем.

Для сравнения используется функция `hmac.compare_digest`, обеспечивающая сравнение без зависимости времени выполнения от совпадающего префикса строк.

### Пароли сервисов

Для защиты паролей сервисов используется алгоритм симметричного шифрования **Fernet** из библиотеки `cryptography`.

При добавлении нового пароля:

1. Получается ключ шифрования на основе мастер-пароля и отдельной случайной соли.
2. Пароль шифруется с помощью Fernet.
3. В `storage.json` сохраняется зашифрованное значение.

При получении пароля выполняется обратная операция — расшифрование с использованием того же ключа.

### Ключ шифрования

Ключ шифрования не хранится в файлах проекта.

Для его получения используется алгоритм **PBKDF2-HMAC-SHA256** с 600 000 итерациями и отдельной случайной солью размером 16 байт.

При первоначальной настройке мастер-пароля генерируется дополнительная соль, которая сохраняется в `master.json` вместе с солью и хэшем мастер-пароля.

При каждом успешном входе ключ шифрования заново вычисляется из введённого мастер-пароля и сохранённой соли. Благодаря этому для одного и того же мастер-пароля и соли всегда получается одинаковый ключ.

Полученный ключ хранится только в памяти программы и используется для шифрования и расшифрования паролей.

При блокировке менеджера ссылка на ключ удаляется из памяти объекта.

### Защита конфиденциальных данных

Следующие файлы исключены из Git с помощью `.gitignore`:

- `src/data/master.json` — содержит соль и хэш мастер-пароля, а также соль для получения ключа шифрования.
- `src/data/storage.json` — содержит названия сервисов и зашифрованные пароли.

Таким образом, конфиденциальные данные пользователя остаются локально и не загружаются в удалённый репозиторий.

## Использование

После запуска приложения необходимо создать мастер-пароль или ввести уже существующий.

Доступные команды:

| Команда         | Назначение                           |
| --------------- | ------------------------------------ |
| `add`           | Добавить новый пароль                |
| `list`          | Показать список сохранённых сервисов |
| `get <name>`    | Получить пароль указанного сервиса   |
| `delete <name>` | Удалить пароль указанного сервиса    |
| `exit`          | Завершить работу                     |

При добавлении пароля можно выбрать автоматическую генерацию или ввести собственный пароль.

## Тестирование

Для запуска тестов используется Pytest:

```bash
uv run pytest -v
```

Тесты проверяют:

- Корректность авторизации с правильным и неправильным мастер-паролем.
- Защиту от повторной инициализации мастер-пароля.
- Добавление, просмотр и получение паролей.
- Удаление сохранённых записей.
- Отсутствие открытых паролей в JSON-файлах.
- Корректность шифрования, расшифрования и хэширования.


## Проверка качества кода

Для проверки кода на соответствие стилю и поиска потенциальных ошибок используется **Ruff**.

Запустить проверку можно командой:

```bash
uv run ruff check
```

Для проверки форматирования кода:

```bash
uv run ruff format
```
